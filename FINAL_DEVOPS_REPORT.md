## ⚡ **Быстрое решение (5 минут):**

### **1. Создать переменные окружения:**
```bash
cd /home/ubuntu/cloudbridge-relay-installer
cat > .env << EOF
RELAY_JWT_SECRET=fallback-key
RELAY_HTTP_PORT=8080
RELAY_P2P_PORT=8082
RELAY_QUIC_PORT=9090
RELAY_STUN_PORT=19302
RELAY_MASQUE_PORT=8443
RELAY_ENHANCED_QUIC_PORT=9092
EOF
```

### **2. Остановить старые процессы:**
```bash
sudo pkill -f cloudbridge-relay
```

### **3. Запустить сервис:**
```bash
export RELAY_JWT_SECRET=fallback-key
./cloudbridge-relay --config configs/config.json &
```

### **4. Проверить порты:**
```bash
sudo netstat -tlnp | grep -E ":(8080|8082|19302|9090|8443|9092)"
```

## 🚀 **Суть проекта CloudBridge Relay:**

### **Что это:**
P2P mesh сеть для создания "почти LAN" соединений между серверами клиентов через наш relay сервер.

### **Проблема, которую решаем:**
- NAT/Firewall блокируют прямые P2P соединения
- Корпоративные сети блокируют P2P протоколы
- Сложность настройки традиционных VPN решений
- Нестабильность существующих решений

### **Наше решение:**
- **Все соединения outbound**: Клиент подключается к нам, мы соединяем с другими
- **Современные протоколы**: QUIC + ICE/STUN/TURN для максимальной совместимости
- **Автоматический fallback**: Если прямое соединение не работает, используем relay
- **Простота настройки**: Клиент просто подключается к нашему серверу

### **Технологии:**
- **QUIC**: Основной транспорт с мультиплексированием и connection migration
- **ICE/STUN/TURN**: NAT traversal для обхода файрволов
- **MASQUE**: HTTP/3 прокси для корпоративных сетей
- **WebSocket/TCP**: Fallback для обхода блокировок
