# 🌐 CloudBridge Relay: P2P Mesh Network

## 🎯 **Суть проекта**

### **Что это такое:**
CloudBridge Relay - это современная P2P mesh сеть, которая позволяет серверам клиентов подключаться друг к другу через наш relay сервер, создавая "почти LAN" опыт без необходимости открывать порты на стороне клиента.

### **Проблема, которую решаем:**
- **NAT/Firewall**: Клиенты за NAT не могут подключаться друг к другу напрямую
- **Корпоративные сети**: Строгие файрволы блокируют P2P соединения
- **Сложность настройки**: Традиционные VPN решения требуют сложной настройки
- **Нестабильность**: WireGuard и другие решения нестабильны в некоторых сетях

### **Наше решение:**
- **Все соединения outbound**: Клиент подключается к нам, мы соединяем с другими клиентами
- **Современные протоколы**: QUIC + ICE/STUN/TURN для максимальной совместимости
- **Автоматический fallback**: Если прямое соединение не работает, используем relay
- **Простота настройки**: Клиент просто подключается к нашему серверу
- **JWT-аутентификация**: Безопасная аутентификация с детальной конфигурацией сети

## 🏗️ **Архитектура**

### **Компоненты:**

#### **1. Relay сервер (наш):**
- **HTTP API (8080)**: Регистрация клиентов, управление сессиями
- **P2P API (8082)**: ICE signaling, управление P2P соединениями
- **STUN Server (19302)**: NAT discovery для клиентов
- **QUIC Transport (9090)**: Основной транспорт для P2P данных
- **MASQUE Proxy (8443)**: HTTP/3 прокси для корпоративных сетей
- **Enhanced QUIC (9092)**: Расширенный QUIC с дополнительными функциями

#### **2. Клиент:**
- Подключается к relay серверу
- Получает список других клиентов
- Устанавливает P2P соединения через ICE/STUN/TURN
- Использует QUIC для передачи данных

### **Схема работы:**

```
Клиент A (LAN) ←→ Relay Server ←→ Клиент B (LAN)
     ↓                                    ↓
  NAT/Firewall                        NAT/Firewall
     ↓                                    ↓
  Интернет ←→ QUIC + ICE/STUN/TURN ←→ Интернет
```

### **JWT-аутентификация:**

Каждый клиент получает JWT токен с полной конфигурацией сети:

#### **Header:**
```json
{
  "alg": "HS256",
  "typ": "JWT", 
  "kid": "fallback-key"
}
```

#### **Payload содержит:**
- **Основные параметры**: `protocol_type`, `scope`, `tenant_id`, `server_id`
- **Сетевую конфигурацию**: `subnet`, `gateway`, `dns`, `mtu`, `firewall_rules`
- **QUIC настройки**: `handshake_timeout`, `idle_timeout`, `max_streams`
- **ICE конфигурацию**: `stun_servers`, `turn_servers`, `candidate_types`
- **MASQUE прокси**: `proxy_url`, `alpn_protocols`, `fallback_enabled`
- **Mesh сеть**: `network_id`, `routing_strategy`, `max_peers`
- **Relay endpoints**: Все адреса серверов (HTTP API, P2P API, QUIC, STUN, MASQUE)

## 🔧 **Технологии**

### **Протоколы:**

#### **QUIC (RFC 9000/9001):**
- **Мультиплексирование**: Множество потоков в одном соединении
- **Низкая задержка**: 0-RTT через TLS 1.3
- **Connection migration**: Автоматическое переключение при смене IP
- **Надежность**: Встроенная защита от потери пакетов

#### **ICE/STUN/TURN:**
- **ICE**: Interactive Connectivity Establishment для NAT traversal
- **STUN**: Session Traversal Utilities for NAT для обнаружения внешнего IP
- **TURN**: Traversal Using Relays around NAT для обхода строгих NAT

#### **MASQUE (RFC 9298):**
- **CONNECT-UDP**: UDP через HTTP/3 для обхода корпоративных прокси
- **Совместимость**: Работает через стандартные HTTP порты
- **Безопасность**: TLS 1.3 шифрование

### **Fallback стратегия:**
1. **Прямое P2P**: QUIC соединение напрямую между клиентами
2. **Relay через QUIC**: Если прямое соединение не работает
3. **MASQUE**: Если QUIC заблокирован, используем HTTP/3
4. **WebSocket**: Если HTTP/3 заблокирован, используем WebSocket
5. **TCP**: Последний fallback через TCP туннель

## 🎯 **Преимущества**

### **Для клиентов:**
- **Безопасность**: Не нужно открывать порты
- **Простота**: Простое подключение к relay серверу
- **Надежность**: Автоматический fallback при проблемах
- **Производительность**: Прямые P2P соединения когда возможно

### **Для нас:**
- **Масштабируемость**: Можем обслуживать множество клиентов
- **Мониторинг**: Видим все соединения и можем их анализировать
- **Управление**: Можем контролировать доступ и качество сервиса
- **Монетизация**: Можем взимать плату за использование

### **❌ Что нужно исправить:**
- Переменная окружения `RELAY_JWT_SECRET` не настроена в .env файле
- Сервис использует дефолтный JWT секрет вместо настроенного
- Нужно добавить `RELAY_JWT_SECRET=fallback-key` в .env файл
