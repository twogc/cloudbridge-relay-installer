## 2GC CloudBridge Global Network — Обзор (будущее состояние)

Коротко: 2GC CloudBridge — это Zero-Trust, latency-aware p2p/relay сеть с федеративным control-plane, мульти‑протокольной передачей (QUIC/HTTP/2/WebSocket поверх WireGuard), предиктивным автоскейлом и строгими SLO. Ниже — целевое видение после исправления безопасности и реализации масштабирования.

### 1. Архитектурное видение

- Безопасный data‑plane: защищённый бинарный протокол с ALPN/TLS 1.3, явные рукопожатия; QUIC поверх WireGuard; connection migration на уровне QUIC и автоматический переключатель протоколов; MP‑QUIC — experimental/flag.
- Федеративный control‑plane: меж‑DC обмен телеметрией и политиками (гео, RTT, loss, jitter, ёмкость, стоимость), eventual‑консистентность с TTL и быстрыми инвалидациями.
- Workload identity by default: SPIFFE/SPIRE, mTLS c SVID, отдельные trust‑domains для control‑plane и tenant‑плоскости.
- Пер‑тенант изоляция: политики, лимиты, quotas; геопиннинг и контроль локализации данных.

### 2. Безопасность (исправленные допущения)

- Валидация токенов по умолчанию: JWKS/Keycloak (aud/iss/exp/nbf), кэш JWKS, ротация ключей; back‑channel logout.
- mTLS между всеми relay и служебными сервисами (SPIFFE), ротация сертификатов, запрет 0‑RTT для control‑plane; на data‑plane допускается 0‑RTT только для идемпотентных операций.
- Никаких хардкодов секретов: только secret‑store/vault; политики минимально необходимых привилегий и явные ACL.
- Ограничение поверхности: строгий CORS, глобальные rate‑limits, backpressure, circuit‑breaker, safe defaults.

### 3. Маршрутизация и выбор пути

- Политики: latency‑aware + capacity‑aware + cost‑aware; tenant‑affinity; blacklisting деградаций; canary/weighted overrides.
- Объяснимость: decision‑лог (RTT, jitter, loss, вес, штрафы) как часть OpenTelemetry traces/logs для аудита и дебага.
- Меж‑relay туннели: пред‑установленные WireGuard‑линки, QUIC over WG; активные пробы формируют RTT‑матрицу по всем рёбрам.

### 4. Масштабирование (реализовано)

- На кластере: HPA/VPA по активным туннелям, p95, очередям accept, error‑rate (включая кастомные метрики); горизонтальное масштабирование relay‑нод.
- На федерации: GeoDNS/Anycast со steered‑весами; перераспределение входа между регионами при перегрузке/деградации.
- Capacity guarding: per‑tenant caps и Kubernetes ResourceQuota/LimitRange как «safety caps» на уровне namespace предотвращают «шумных соседей».

Что это даёт:

- Снижение задержек на 20–40% (местами до 60%) за счёт egress ближе к цели и latency‑aware steering.
- Доступность 99.95–99.99%: авто‑фейловер маршрутов, миграция активных туннелей без разрыва.
- Линейный рост пропускной способности при добавлении регионов/нод; быстрый онбординг новых DC.
- Управляемая стоимость: cost‑aware egress и взвешенные политики снижают расходы при сохранении SLO.

### 5. Наблюдаемость и SLO

- OpenTelemetry (traces/metrics/logs) + Prometheus/Grafana; сквозная трассировка по ID туннеля A→B→peer.
- SLI: p95 RTT, p99.9 loss, failover‑time, время конвергенции маршрута, % авто‑переключений, SLO‑усталость.
- Алертинги и автодеградация: понижение веса/исключение ребра, быстрый re‑route, объяснимые события.

### 6. Data residency и комплаенс

- Геопиннинг/локализация: региональные boundary для ключей/метаданных; чёткие политики «где расшифровка». Для периметра и работы с TLS‑ключами: Cloudflare Data Localization Suite (DLS) + Geo Key Manager/Keyless SSL для регионального хранения/управления ключами; учитывать добавочный RTT при удалённом key‑server (обычно одноразовый на установку сессии).
- Аудит политик: неизменяемые журналы (append‑only) с криптографической верификацией изменений.

### 7. Операции и DX

- Профили окружений (dev/stage/prod) со строгими безопасными дефолтами.
- Runbook’и инцидентов: деградация канала, отказ региона, drain & re‑route, объяснимые причины решений.
- Конфиги «как код»: политики роутинга, веса и лимиты управляются декларативно и откатываемы.

### 8. Ограничения и оговорки

- Multipath‑QUIC — эксперимент: в проде применяются connection migration и мульти‑каналы active/standby; MP‑QUIC включается по флагу эксперимента.
- Цифры ускорения чувствительны к географии и last‑mile; целевой коридор 20–40% для TTFB/RTT — реалистичная средняя оценка.

### 9. Резюме ценности

2GC CloudBridge превращает глобальную сеть в программируемый, безопасный и объяснимый транспортный слой: 
— минимальные задержки за счёт латентностной осведомлённости,
— высокая доступность благодаря федеративному control‑plane и самовосстановлению,
— экономичность через cost‑aware egress,
— уверенность для регуляторов и клиентов за счёт строгой идентичности, телеметрии и контроля местонахождения данных.
