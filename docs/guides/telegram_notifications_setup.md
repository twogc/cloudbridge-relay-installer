# Настройка Telegram уведомлений для Lynis

## Обзор

Скрипт `scripts/lynis_with_telegram.sh` позволяет запускать аудит безопасности Lynis и автоматически отправлять результаты в Telegram. **Новая функция**: скрипт отправляет уведомления только при обнаружении изменений в результатах аудита.

## Основные возможности

- ✅ **Отслеживание изменений**: Уведомления отправляются только при обнаружении новых проблем или изменений
- 🔄 **Сравнение результатов**: Автоматическое сравнение с предыдущими результатами
- 📊 **Детальная аналитика**: Подробный анализ изменений в безопасности
- 🚨 **Критические уведомления**: Принудительная отправка при необходимости
- 📝 **Логирование изменений**: Ведение журнала всех обнаруженных изменений

## Настройка Telegram бота

### 1. Создание бота

1. Откройте Telegram и найдите @BotFather
2. Отправьте команду `/newbot`
3. Следуйте инструкциям:
   - Введите имя бота (например, "CloudBridge Security Bot")
   - Введите username бота (должен заканчиваться на 'bot', например "cloudbridge_security_bot")
4. Сохраните токен бота (выглядит как `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`)

### 2. Получение Chat ID

#### Вариант 1: Личный чат
1. Найдите вашего бота по username
2. Отправьте ему любое сообщение (например, "/start")
3. Откройте в браузере: `https://api.telegram.org/bot<TOKEN>/getUpdates`
4. Найдите в ответе `"chat":{"id":123456789}` - это ваш Chat ID

#### Вариант 2: Групповой чат
1. Добавьте бота в группу
2. Отправьте сообщение в группу
3. Проверьте `https://api.telegram.org/bot<TOKEN>/getUpdates`
4. Chat ID группы будет отрицательным числом

### 3. Настройка скрипта

Откройте файл `scripts/lynis_with_telegram.sh` и измените строки:

```bash
TELEGRAM_BOT_TOKEN="ваш_токен_бота"
TELEGRAM_CHAT_ID="ваш_chat_id"
```

### 4. Установка зависимостей

Для корректной работы отслеживания изменений рекомендуется установить `jq`:

```bash
sudo apt-get install jq
```

## Использование

### Запуск аудита с уведомлениями
```bash
sudo ./scripts/lynis_with_telegram.sh
```

### Тестовая отправка
```bash
sudo ./scripts/lynis_with_telegram.sh --test
```

### Сброс состояния отслеживания
```bash
sudo ./scripts/lynis_with_telegram.sh --reset
```

### Принудительная отправка (игнорируя изменения)
```bash
sudo ./scripts/lynis_with_telegram.sh --force
```

### Показать справку по настройке
```bash
./scripts/lynis_with_telegram.sh --setup
```

## Как работает отслеживание изменений

### Сохранение состояния
Скрипт сохраняет результаты каждого аудита в файл `/var/lib/lynis-telegram/previous_results.json`:
- Hardening Index (индекс безопасности)
- Количество предупреждений
- Количество рекомендаций  
- Количество проблем безопасности
- Список конкретных проблем и рекомендаций

### Сравнение результатов
При каждом запуске скрипт сравнивает текущие результаты с предыдущими и отправляет уведомление только при обнаружении:
- Изменения Hardening Index
- Новых предупреждений
- Новых проблем безопасности
- Изменения количества рекомендаций

### Пример сообщения с изменениями

## Автоматизация

### Запуск по расписанию (cron)

Добавьте в crontab для ежедневного запуска в 2:00:
```bash
sudo crontab -e
```

Добавьте строку:
```
0 2 * * * /home/ubuntu/cloudbridge-relay-installer/scripts/lynis_with_telegram.sh
```

### Запуск после обновлений системы

Создайте скрипт для автоматического запуска после обновлений:
```bash
sudo nano /etc/apt/apt.conf.d/99-lynis-audit
```

Добавьте:
```
DPkg::Post-Invoke {"cd /home/ubuntu/cloudbridge-relay-installer && ./scripts/lynis_with_telegram.sh";};
```

## Файлы состояния

Скрипт создает и использует следующие файлы в `/var/lib/lynis-telegram/`:

- `previous_results.json` - результаты предыдущего аудита
- `current_results.json` - результаты текущего аудита  
- `changes.log` - журнал всех обнаруженных изменений

## Безопасность

- Токен бота должен быть секретным
- Не публикуйте токен в публичных репозиториях
- Используйте переменные окружения для продакшена:
  ```bash
  export TELEGRAM_BOT_TOKEN="ваш_токен"
  export TELEGRAM_CHAT_ID="ваш_chat_id"
  ```
- Файлы состояния хранятся в защищенной директории `/var/lib/lynis-telegram/`

## Устранение неполадок

### Ошибка отправки сообщения
1. Проверьте правильность токена и Chat ID
2. Убедитесь, что бот добавлен в чат
3. Проверьте интернет-соединение

### Бот не отвечает
1. Отправьте команду `/start` боту
2. Проверьте права бота в группе (если используется групповой чат)

### Проблемы с отслеживанием изменений
1. Убедитесь, что установлен `jq`: `sudo apt-get install jq`
2. Проверьте права доступа к `/var/lib/lynis-telegram/`
3. Сбросьте состояние: `sudo ./scripts/lynis_with_telegram.sh --reset`

### Ошибки в логах
Проверьте файл лога Lynis для детальной информации о проблемах безопасности.

## Защита от параллельного запуска и зависших процессов

- Скрипт и systemd unit защищают от одновременного запуска нескольких процессов Lynis:
  - Используется lock-файл (`/var/run/lynis_telegram.lock`) и PID-файл (`/var/run/lynis_telegram.pid`).
  - Если процесс завис или был убит, lock-файл и PID-файл автоматически очищаются при следующем запуске.
  - В systemd unit используется `ExecStartPre` с `flock`, чтобы не запускать второй процесс, если первый ещё работает.
  - В unit-файле включён автоматический перезапуск при сбое (`Restart=on-failure`).

### Как это работает
- Если Lynis уже запущен, второй запуск завершится с ошибкой, а в логах будет предупреждение.
- Если процесс был убит или завис, lock-файл будет удалён автоматически при следующем запуске.
- Если сервис завершился с ошибкой, systemd попробует перезапустить его через 30 секунд.

### Ручная очистка lock-файла
Если требуется вручную сбросить lock-файл и PID-файл:
```bash
sudo rm -f /var/run/lynis_telegram.lock /var/run/lynis_telegram.pid
```

### Проверка статуса
```bash
sudo systemctl status lynis-security-audit.service
sudo journalctl -u lynis-security-audit.service -f
```
