# Best Practices по безопасности для Keycloak Multi-Tenancy

## 1. Аутентификация и авторизация
- Включайте MFA для всех администраторов и критических пользователей.
- Используйте password policy (минимальная длина, сложность, срок действия пароля).
- Включите email verification для всех пользователей.
- Используйте session management: ограничение времени жизни сессии, idle timeout, single session per user (если требуется).

## 2. Изоляция данных
- Для каждой компании используйте отдельный realm или tenant-атрибуты.
- Группы, роли, клиенты должны быть изолированы по арендаторам.
- Проверяйте tenant claims в backend-сервисах (active_tenant, all_tenants).
- Не допускайте пересечения пользователей между арендаторами.

## 3. Работа с JWT
- Проверяйте подпись, срок действия, issuer, audience, tenant claims.
- Используйте короткое время жизни access token (5-15 мин), refresh token — по необходимости.
- Включите rotation и blacklisting refresh tokens.
- Не храните токены в localStorage на фронте — используйте httpOnly cookies или secure storage.

## 4. Хранение секретов
- Все пароли, client secret, bind credentials храните только в защищённых хранилищах (Vault, Kubernetes secrets).
- Не коммитьте секреты в git!
- Используйте переменные окружения для передачи секретов в контейнеры.

## 5. Аудит и логирование
- Включите аудит всех критических операций: создание/удаление арендаторов, добавление пользователей, смена ролей, интеграция IDP.
- Логи должны содержать user_id, tenant_id, operation, timestamp, результат.
- Настройте ротацию логов и защиту от tampering.

## 6. DevSecOps
- Включите автоматический security scanning (gosec, gitleaks, Snyk) в CI/CD.
- Регулярно обновляйте зависимости Keycloak и расширений.
- Используйте только TLS 1.2+ (лучше 1.3) для всех соединений.
- Включите автоматическую ротацию сертификатов.

## 7. Чеклист безопасности
- [ ] MFA включена для админов и критических пользователей
- [ ] Password policy настроена
- [ ] Email verification включена
- [ ] Изоляция данных между арендаторами
- [ ] JWT claims валидируются во всех сервисах
- [ ] Секреты не хранятся в git/файлах
- [ ] Аудит и ротация логов настроены
- [ ] Security scanning в CI/CD
- [ ] TLS 1.3 для всех соединений
