## **Структура репозиториев**

### **🚀 1. QUIC-first + MASQUE (3 репозитория)**
- `masque-go` - CONNECT-UDP реализация
- `connect-ip-go` - CONNECT-IP реализация  
- `masquerade` - Rust альтернатива

### **🌐 2. ICE/STUN/TURN + Метрики (4 репозитория)**
- `ice` - Pion ICE реализация
- `stun` - Pion STUN протокол
- `coturn` - TURN сервер с метриками
- `go-stun` - Альтернативная STUN/TURN/ICE

### **🔒 3. WireGuard (2 репозитория)**
- `wireguard-go` - Userspace WireGuard
- `wgctrl-go` - Управление WG интерфейсами

### ** 4. Fallback механизмы (3 репозитория)**
- `tailscale` - DERP релей
- `wstunnel` - WebSocket туннелирование
- `websocket` - Gorilla WebSocket библиотека

### **📚 5. Дополнительные (5 репозиториев)**
- `openp2p` - P2P сеть с NAT traversal
- `p2pquic` - P2P поверх QUIC
- `quic-p2p` - P2P сеть на базе QUIC
- `quicssh` - SSH поверх QUIC
- `reverse-http` - Reverse HTTP туннели

## **Как использовать референсные репозитории**

### **Для разработки CloudBridge Relay:**

1. **MASQUE компонент**:
   - Изучить `masque-go/` для CONNECT-UDP
   - Изучить `connect-ip-go/` для CONNECT-IP
   - Адаптировать под нашу архитектуру

2. **ICE/STUN/TURN слой**:
   - Использовать `pion/ice/` для NAT traversal
   - Изучить `coturn/` для TURN сервера с метриками
   - Адаптировать метрики под Prometheus

3. **WireGuard fallback**:
   - Изучить `wireguard-go/` для userspace WG
   - Использовать `wgctrl-go/` для управления интерфейсами

4. **Fallback механизмы**:
   - Изучить `tailscale/` для DERP релея
   - Использовать `wstunnel/` для WebSocket fallback

### **Ключевые паттерны для изучения:**

- **HTTP/3 + QUIC datagrams** - из `masque-go/`
- **NAT traversal** - из `pion/ice/`
- **TURN сервер с метриками** - из `coturn/`
- **WebSocket fallback** - из `wstunnel/`
- **DERP релей** - из `tailscale/`
