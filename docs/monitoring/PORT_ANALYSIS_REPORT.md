## **Возможные причины проблемы**

### **1. HTTP/3 сервер не может привязаться к порту**
- **Причина**: Ошибка при запуске HTTP/3 сервера
- **Симптом**: Нет сообщения об успешном запуске
- **Решение**: Проверить TLS конфигурацию

### **2. Проблема с TLS сертификатами**
- **Причина**: Невалидные или поврежденные сертификаты
- **Симптом**: HTTP/3 сервер падает при запуске
- **Решение**: Пересоздать TLS секрет

### **3. Конфликт портов**
- **Причина**: Порт 8443 занят другим процессом
- **Симптом**: Ошибка привязки к порту
- **Решение**: Проверить использование порта

### **4. Проблема с HTTP/3 библиотекой**
- **Причина**: Ошибка в quic-go библиотеке
- **Симптом**: Сервер запускается, но не слушает
- **Решение**: Обновить зависимости

## 🔧 **Рекомендации по исправлению**

### **1. Немедленные действия**:
```bash
# Проверить TLS сертификаты
kubectl get secret cloudbridge-tls -n cloudbridge -o yaml

# Пересоздать TLS секрет
kubectl delete secret cloudbridge-tls -n cloudbridge
kubectl create secret tls cloudbridge-tls --cert=tls.crt --key=tls.key -n cloudbridge

# Перезапустить поды
kubectl rollout restart deployment/cloudbridge-relay -n cloudbridge
```

### **2. Диагностика**:
```bash
# Проверить логи MASQUE сервера
kubectl logs deployment/cloudbridge-relay -n cloudbridge | grep -i masque

# Проверить порты в контейнере
kubectl exec -it pod -- netstat -tlnp

# Проверить TLS конфигурацию
kubectl exec -it pod -- ls -la /app/certs/
```

### **3. Альтернативные решения**:
- **Использовать HTTP/2 вместо HTTP/3** для MASQUE
- **Настроить MASQUE на другом порту** (например, 8444)
- **Проверить совместимость quic-go версии**
