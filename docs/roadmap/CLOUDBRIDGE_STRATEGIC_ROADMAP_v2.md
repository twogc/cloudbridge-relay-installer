# CloudBridge Relay - Roadmap: Масштабирование и подготовка к сертификации

## 1. Масштабирование платформы

### 1.1. Производительность и HA

* Добавить **multi-arch Docker-образы** (x86_64 + ARM64).
* Настроить **HPA/VPA** для relay-сервера в Kubernetes.
* Ввести **multi-region** развертывания (RU/EU/Asia) с балансировкой Anycast/DNS.
* Тестирование отказоустойчивости: симуляции падений нод, сетевых сбоев.
* Валидация целевых SLO: p95 < 200мс, uptime ≥ 99.9%.

### 1.2. Наблюдаемость и эксплуатация

* Углубить мониторинг (Prometheus + Grafana, алерты в Alertmanager).
* Централизованные логи (ELK/OpenSearch, ретеншн ≥ 90 дней).
* Tracing (OpenTelemetry) для API и P2P-потоков.
* Runbooks для инцидентов (DoS, отказ кластера, сбой авторизации).

### 1.3. Сетевые и протокольные оптимизации

* Нагрузочные тесты на QUIC/MASQUE/ICE.
* Fine-tuning NAT/TURN пула.
* Поддержка IPv6 и dual-stack сценариев.
* Тесты site-to-site VPN в режиме WireGuard fallback.

---

## 2. Подготовка к сертификации и комплаенсу

### 2.1. Безопасность

* Внедрить **политику ротации ключей** (TLS, Zitadel JWKS).
* Включить **mTLS** между сервисами (Relay ↔ API ↔ DB).
* Rate limiting / WAF на Ingress.
* DLP-контуры: исключить утечки PII/ключей из логов.
* Внедрить Post-Quantum Crypto (Kyber/Dilithium) в тестовом режиме.

### 2.2. Документы и процессы (ФСТЭК/ISO)

* Подготовить **политику безопасности** (инфраструктурная, организационная).
* Внедрить **логирование событий безопасности** (аутентификация, изменение конфигураций, админ-операции).
* Создать **процедуры управления уязвимостями** (сканирование, обновления, инциденты).
* Провести **риск-анализ ИБ** (угрозы, векторы атак, меры защиты).
* Завести **матрицу контроля доступа** (RBAC, multi-tenancy).
* Документировать **SDLC** (жизненный цикл разработки с учётом безопасных практик).

### 2.3. Инфраструктура для соответствия

* Разделение сред (dev/stage/prod) с отдельными ключами.
* Vault/ExternalSecrets для хранения секретов.
* Системы резервного копирования и восстановления (RTO/RPO документированы).
* Аудит соответствия требованиям ФСТЭК (152-ФЗ, 187-ФЗ).
* ISO 27001/27017/27018: подготовка ISMS (Information Security Management System).

---

## 3. Финальные шаги перед сертификацией

* Провести **внутренний аудит** (по чек-листу ISO/ФСТЭК).
* Зафиксировать **версии компонентов** (Keycloak заменён на Zitadel, Go, PostgreSQL и т. д.).
* Провести **Pen-test** с внешними специалистами.
* Организовать **пилот у клиента** (для проверки SLA/документации).
* Подать заявку на сертификацию (ФСТЭК) и пройти аудит ISO.

## Текущий статус

### Завершенные задачи:
- Миграция с Keycloak на Zitadel
- Реализация MASQUE/QUIC/P2P протоколов
- Базовый мониторинг и логирование
- Kubernetes развертывание
- Cadence workflow engine
- Thread-safe компоненты
- Go 1.25 совместимость

### Приоритетные задачи для старта:
1. **Multi-arch Docker images** - расширение поддержки платформ
2. **HPA/VPA настройка** - автоматическое масштабирование
3. **Углубленный мониторинг** - Prometheus + Grafana dashboards
4. **mTLS между сервисами** - повышение безопасности
5. **Политика ротации ключей** - автоматизация управления сертификатами

### Метрики готовности к сертификации:
- **Безопасность**: 60% (базовые меры реализованы)
- **Производительность**: 70% (основные компоненты работают)
- **Наблюдаемость**: 50% (базовый мониторинг есть)
- **Документация**: 40% (техническая документация готова)
- **Процессы**: 20% (требуется создание формальных процедур)

**Общая готовность к сертификации: 48%**
