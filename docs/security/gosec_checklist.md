# Чек-лист по устранению уязвимостей Go (gosec)

## 1. Integer Overflow (G115, CWE-190)
- Проверьте все места, где происходит преобразование типов (например, int → int32).
- Добавьте проверки на переполнение перед преобразованием.
- Используйте безопасные функции для работы с числами.

**Пример:**  
`cmd/relay/main.go:295`

---

## 2. TLS MinVersion слишком низкий (G402, CWE-295)
- Убедитесь, что используется не менее TLS 1.2 (`tls.Config{MinVersion: tls.VersionTLS12}`).
- Не разрешайте устаревшие версии TLS.

**Пример:**  
`internal/tls/tls.go:43-47`

---

## 3. HTTP сервер без таймаутов (G114, CWE-676)
- Всегда задавайте таймауты для http.Server:
  - `ReadTimeout`
  - `WriteTimeout`
  - `IdleTimeout`

**Пример:**  
`internal/metrics/http.go:26`

---

## 4. Потенциальное включение файлов через переменные (G304, CWE-22)
- Не используйте переменные из внешнего ввода для путей к файлам без валидации.
- Используйте белые списки разрешённых файлов/директорий.

**Примеры:**  
`internal/tls/tls.go:177`  
`config/config.go:215`

---

## 5. Неправильные права на файлы/директории (G302, G301, CWE-276)
- Все чувствительные файлы (ключи, конфиги) должны иметь права не выше 0600.
- Директории — не выше 0750.
- Проверьте создание файлов/директорий через os.OpenFile, os.Mkdir и т.д.

**Примеры:**  
`cmd/relay/main.go:76`  
`internal/logger/logger.go:413, :85`

---

## 6. Необработанные ошибки (G104, CWE-703)
- Всегда обрабатывайте возвращаемые ошибки.
- Не игнорируйте ошибки функций, особенно при работе с файлами, сетью, БД.

**Примеры:**  
`internal/tunnel/tunnel.go:199, :195`

---

## 7. Общие рекомендации
- Проверьте все предупреждения gosec, даже если они кажутся малозначительными.
- Используйте линтеры и автоматические проверки в CI/CD.
- После исправлений — повторно прогоняйте gosec.

---

**Рекомендуемое действие:**
1. Исправить HIGH/CRITICAL уязвимости в первую очередь.
2. Провести code review с фокусом на безопасность.
3. Внедрить автоматический аудит (gosec, safety, lynis) в CI/CD.
