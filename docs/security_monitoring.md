# Система мониторинга безопасности

## Обзор

Система автоматического мониторинга безопасности CloudBridge Relay отслеживает различные аспекты безопасности сервера и отправляет уведомления в Telegram при обнаружении проблем.

## Что отслеживается

### 🔒 Безопасность
- **Новые блокировки Fail2Ban** - уведомления о новых заблокированных IP
- **Подозрительная активность SSH** - множественные неудачные попытки входа
- **Критические сервисы** - статус UFW, Fail2Ban, SSH, rsyslog
- **Процессы от root** - мониторинг количества процессов от root

### 💾 Системные ресурсы
- **Дисковое пространство** - предупреждения при использовании >85%
- **Обновления системы** - уведомления о доступных обновлениях (>10 пакетов)

### 🔐 SSL сертификаты
- **Срок действия** - предупреждения за 30 дней до истечения

### 📋 Логи системы
- **Критические ошибки** - мониторинг ошибок в системных логах

## Установка и настройка

### Быстрая установка
```bash
sudo ./scripts/setup_security_monitor.sh install
```

### Ручная установка
1. Установить systemd сервис:
   ```bash
   sudo ./scripts/setup_security_monitor.sh install
   ```

2. Проверить статус:
   ```bash
   sudo ./scripts/setup_security_monitor.sh status
   ```

3. Протестировать уведомления:
   ```bash
   ./scripts/security_monitor.sh --test
   ```

## Управление сервисом

### Команды управления
```bash
# Запуск сервиса
sudo ./scripts/setup_security_monitor.sh start

# Остановка сервиса
sudo ./scripts/setup_security_monitor.sh stop

# Перезапуск сервиса
sudo ./scripts/setup_security_monitor.sh restart

# Проверка статуса
sudo ./scripts/setup_security_monitor.sh status

# Удаление сервиса
sudo ./scripts/setup_security_monitor.sh uninstall
```

### Ручной запуск
```bash
# Разовая проверка
./scripts/security_monitor.sh --once

# Непрерывный мониторинг
./scripts/security_monitor.sh --continuous

# Тестовая отправка
./scripts/security_monitor.sh --test
```

## Конфигурация

### Настройка интервалов проверки
Отредактируйте `scripts/security_monitor.sh`:
```bash
CHECK_INTERVAL=300  # 5 минут (в секундах)
```

### Настройка порогов
```bash
# Дисковое пространство (процент)
local threshold=85

# SSH неудачные попытки
if [[ $ssh_failures -gt 50 ]]; then

# Процессы от root
if [[ $root_processes -gt 20 ]]; then

# Обновления системы
if [[ $updates_count -gt 10 ]]; then
```

### Настройка Telegram
Отредактируйте в `scripts/security_monitor.sh`:
```bash
TELEGRAM_BOT_TOKEN="ваш_токен_бота"
TELEGRAM_CHAT_ID="ваш_chat_id"
```

## Логирование

### Файлы логов
- `logs/security-monitor.log` - основной лог мониторинга
- `logs/security-alerts.log` - лог уведомлений
- `logs/last_fail2ban_blocks.txt` - последние блокировки Fail2Ban

### Просмотр логов
```bash
# Логи systemd сервиса
sudo journalctl -u security-monitor.service -f

# Логи мониторинга
tail -f logs/security-monitor.log

# Логи уведомлений
tail -f logs/security-alerts.log
```

## Автоматизация

### Автозапуск при загрузке
Сервис автоматически запускается при загрузке системы после установки.

### Интеграция с другими системами
Система может быть интегрирована с:
- Prometheus/Grafana для метрик
- AlertManager для дополнительных уведомлений
- Логирование в центральную систему (ELK Stack)

## Устранение неполадок

### Сервис не запускается
1. Проверьте логи:
   ```bash
   sudo journalctl -u security-monitor.service --no-pager
   ```

2. Проверьте права доступа:
   ```bash
   ls -la scripts/security_monitor.sh
   ```

3. Проверьте конфигурацию Telegram

### Уведомления не отправляются
1. Проверьте токен и Chat ID
2. Убедитесь, что бот добавлен в чат
3. Проверьте интернет-соединение

### Ложные срабатывания
Настройте пороги в конфигурации для уменьшения ложных срабатываний.

## Безопасность

- Сервис запускается от пользователя `ubuntu`
- Использует ограниченные права доступа
- Логи не содержат чувствительной информации
- Токен Telegram должен быть защищен
